Daywell app map

A calm browser companion for desk workers. It measures real time at the desk, credits breaks automatically when you step away, and keeps every number honest: measured, manual, reported, or "No data".

The main pieces

  • Signal sources tell Daywell whether you're at the desk: src/sources/idle.js (Chrome/Edge idle detection) or src/sources/manual.js (the "I'm stepping away / at my desk" buttons).
  • The engine, src/engine.js, is pure logic: events in, a new day record out. It owns sitting stretches, breaks, prompts, snooze, pause, work hours and the daily cap.
  • Helpers: src/water.js (water log and reminder rule), src/habits.js (calories), src/reflection.js (end-of-day summary), src/device.js (what this browser can do).
  • Storage, src/store.js, keeps everything in this browser's localStorage and validates it on load. No server.
  • The interface: index.html + styles.css for structure and look, src/ui/render.js draws the views, src/app.js wires it all together on a 1-second tick.

One action, end to end: walk away and the break logs itself

Reference route 3 stops

Open the files in your editor and search for the anchor in each stop.

  1. src/sources/idle.js, search const report
    The browser fires a change event when you stop using the keyboard and mouse for 60 s or lock the screen. report() turns that into an away event, with since set 60 s earlier because that's when input actually stopped.
  2. src/engine.js, search function onActive and function logBreak
    When you come back, the engine closes the away segment. If it lasted at least the minimum break (2 min by default), logBreak records a measured break, hides any break prompt, and sets the "Welcome back" notice. Shorter gaps merge back into desk time.
  3. src/ui/render.js, search Welcome back.
    renderHero reads day.notice and shows the card with "Undo, I was here". The saved record lives in localStorage via persist() in src/app.js.
The test that pins this behavior

tests/engine.test.js: "away period at or above the minimum logs a measured break and resets the clock", plus "away period shorter than the minimum is merged back into desk time". Run npm test.

A practice to reuse

Turn a wish into an observable rule, then pin it with a test. The original concept said "count steps, calories and screen time". Rather than building features the browser can't honestly support, the PRD turned that into a rule you can check: missing data is shown as "No data", never as zero. That rule became code (caloriesTotal and latestSteps return null, which the UI shows as "No data") and tests (tests/reflection.test.js: empty day says "No data", never zero; tests/habits.test.js).

The same move fixed a real bug. "I didn't get any reminder" was vague. Investigating showed reminders were held outside 09:00–17:00 without saying so. That became an explicit rule, canNudgeNow: nudge during work hours, or when demo speed is on, or when the person chose "Remind me anyway today". It's pinned by the test nudges outside work hours only when overridden for today or in demo speed.

On your next project, when you prompt an agent, describe the outcome someone could observe ("shows No data", "explains why reminders are on hold") instead of the feature name. It's easier for the agent to build and easier for you to check.
